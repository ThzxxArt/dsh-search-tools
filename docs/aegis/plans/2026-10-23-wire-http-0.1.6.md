# 0.1.6 — wire-http local browser-grade fetch adapter

## Goal

Add a third built-in fetch adapter, `wire-http`, that:

- needs no Reader, Docker, API key, browser install, or system library;
- presents Chrome/Firefox TLS and HTTP/2 fingerprints locally through `impit`;
- pins every redirect hop to a validated public IP through a loopback egress guard;
- extracts HTML with the existing Readability path and PDF text with PDF.js;
- keeps the stable `dsh-search-tools-fetch` provider id, the `html|text` `FetchResult` union,
  the default `readable-http` selection, and the existing `readable-http`/`jina-reader`
  behavior unchanged.

The adapter must never claim to execute page JavaScript. SPA pages remain the job of
`jina-reader` or a future opt-in browser backend, and `wire-http` must fail with an
explainable code rather than silently forwarding the URL to a third party.

## Architecture

```text
FetchDispatcher
  -> WireHttpRuntime
     -> shared public target guard (initial URL)
     -> EgressGuard (127.0.0.1, random port)
          CONNECT host:443 -> resolve all addresses -> reject non-public
          -> connect pinned public IP -> TCP tunnel
     -> Worker thread (one request per worker)
          -> impit (browser TLS/HTTP2, redirects, HTTP proxy)
     -> decode bytes
     -> HTML: Readability / Markdown
     -> PDF: pdfjs-dist text extraction
     -> FetchResult
```

The worker is required because `impit` clients have no `close()`; the isolated
prototype with a worker exits 0, while the same request without a worker leaves the
process alive (exit 124 after the timeout). No `FetchAdapterRuntime.dispose` extension is
needed: the worker's lifetime is one request.

## Compatibility boundary

- Provider id `dsh-search-tools-fetch` and search id `dsh-search-tools` do not change.
- `FetchResult` remains `html|text`; PDF text is `text`, not a new union member.
- `DEFAULT_FETCH_SECTION.adapter` remains `readable-http`.
- `jina-reader` public behavior and config keys remain compatible; only its address
  classifier moves to a shared module.
- No automatic fallback from `wire-http` to `jina-reader` or `readable-http`.
- No Cookie Jar, login state, Authorization header, proxy credential, or TLS bypass.
- HTTP/3 is out of scope because the local TCP guard cannot pin it honestly.

### Task 4 — Loopback egress guard

Files: `src/fetch/adapters/wire-http/egress-proxy.ts`, tests.

- Bind only `127.0.0.1` on a random port.
- Support HTTP `CONNECT host:443` and absolute-form HTTP requests.
- For every request/hop: parse host/port, allow only 80/443, resolve DNS, require all
  answers public, connect to one validated IP, and never re-resolve the hostname.
- Reject credentials, non-http(s), URL fragments, private literals, DNS mixed answers,
  loopback, CGNAT, link-local, ULA, IPv4-mapped, 6to4, Teredo, NAT64.

- Tests use a fake resolver and a local fake upstream; assert the target sees a

### Task 5 — Worker transport

Files: `src/fetch/adapters/wire-http/worker.ts`, `transport.ts`,
`src/fetch/adapters/wire-http/protocol.ts`, `tsdown.config.ts`, tests.

- Worker receives `{url, profile, timeoutMs, maxRedirects, proxyUrl, locale}`.
- It loads `impit` only inside the worker, sends no Cookie/Authorization, uses
  `proxyUrl`, follows redirects through the guard, and returns status, final URL,
  headers, and a bounded body as transferable bytes.
- Main thread aborts by terminating the worker; the worker is always terminated in
  `finally`. No persistent native client survives a request.
- Error codes: `WIRE_RUNTIME_UNAVAILABLE`, `WIRE_TIMEOUT`, `WIRE_REDIRECT_BLOCKED`,
  `WIRE_NETWORK`, `WIRE_RESPONSE_TOO_LARGE`, `WIRE_UNSUPPORTED_CONTENT`.
- Build emits `lib/wire-worker.js`; `files` still publishes only `lib`.
- Tests: worker lifecycle (exit, no orphan), abort, bounded body, error mapping, and
  `impit` native load on the current platform.

## Risks and retirement

- `impit` native binaries are platform-specific; CI must cover Linux and Windows and
  local macOS remains an advisory check. `available()` stays config-only; a missing
  native binding surfaces `WIRE_RUNTIME_UNAVAILABLE` at first use, not a silent fallback.
- PDF.js increases bundle/runtime cost; lazy import and page/byte caps are mandatory.
- The loopback guard only covers TCP HTTP/1.1 and HTTP/2; HTTP/3 is deliberately not
  advertised. No old adapter path is retired in 0.1.6.
